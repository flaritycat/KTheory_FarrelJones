## Definitions

**Definition.** A residual-bucket checkpoint is a module whose main output is
a decision about whether the active residual buckets contain a candidate-ready
attack packet, or whether the project must build such a packet before reading
more sources.

**Definition.** A candidate-inventory module is a bounded artifact that scans
the repository's current residual buckets for named groups, families, or
missing bridges and classifies each item as already removed,
candidate-ready, bridge-missing, source-missing, or no-data.

**Warning.** A residual bucket is not candidate-ready merely because it has
an interesting source nearby. It is candidate-ready only when the repository
has a specific group, family, or bridge whose hypotheses can be checked with
a clear stop condition.

### Checkpoint decision

**Route decision.** No remaining residual bucket is candidate-ready enough to
justify another source-verification module as the next step.

This is a project-state decision, not a mathematical negative result. It
does not say that `RB-004`, `RB-005`, `RB-006`, `RB-007`, or `RB-008` is
empty. It says that the repository should now build a candidate inventory
before choosing another theorem source.

**Route decision.** Select `FJ55`, a `T-001` candidate-inventory and
attack-packet builder, as the next module.

The candidate is not one group yet. It is the current `T-001` residual ledger
after the `RB-004`, `RB-005`, and current `RB-006` pauses.

The repository has no current source-verified bridge removing the remaining

By the end of `FJ55`, either select one concrete candidate-ready attack
packet for `FJ56`, or record a no-candidate artifact with the exact reason no

## Stop condition

Do not open a new source lane unless the inventory has named the candidate
and the missing source statement.

## Proof or verification

The no-subtraction proposition follows from the module design. `FJ54` checks
no new group, verifies no new external theorem, and records no new bridge into
the Farrell--Jones known-case routes from `FJ23`--`FJ27`.

The route decision follows from the repository's current ledgers. `FJ43`
requires a candidate before further automatic `RB-004` source-cluster work.
`FJ50` pauses `RB-005` after its finite-index lanes fail to produce an
application. `FJ53` closes the current `RB-006` path as non-subtractive,
leaving only a hyperbolic-overlap route already governed by `FJ23`. The
strategic audit after cycle 002 says that when source work stops producing
route delta, the project should force an attack packet, no-candidate
artifact, or pivot. The next honest artifact is therefore a candidate
inventory.
